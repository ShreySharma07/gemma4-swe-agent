## E2: what the windows supervise

| Check | Result | Meaning |
|---|---|---|
| Tool responses inside supervised spans | **0** | No response leakage into the loss |
| Unclosed tool-call spans / spans with >1 call | **0 / 0** | Boundaries are clean |
| Windows with back-to-back calls (no response between) | **0** | The data never shows batched calls, so Step D's 55–253-call first turns were not copied from it |
| Windows starting mid-run (earlier steps absent) | **817 / 1,017 (80%)** | Most targets are learned without the run's earlier state |
| Source-fix actions (snippet edits) | **396 of 7,361 supervised actions (5%)** | Reads 1,530, scripts run 1,504, searches 1,175, tests 1,051, file writes 735 |
| Snippet edits whose file was *not* shown earlier in the same window | **311 / 396 (79%)** | The read → edit transition is almost never visible in context |
| Supervised-token share | `write_file` **56%**, snippet edits 17%, scripts 8%, final text 6%, reads 4%, search 3%, tests 3% | The loss is dominated by file-writing content |
| What `write_file` writes | 382 new test files, 247 reproduction/debug scripts, 106 other (mostly `final_verification.py`) | That 56% is **scratch-script writing, not source fixes** |

The first supervised action of a mid-run window is: `cat -n` 235, `write_file` 157, run a script 148, `pytest` 120, search 67, **edit 40**.

## What this establishes

1. **Mask and boundary corruption is ruled out.** This is hypothesis 3 in the research report, apart from the analyzer-tool omission already known.
2. **The read → edit transition is missing in context. This is a concrete, measured defect in the data**, supporting hypothesis 1. In 79% of source fixes, the file being fixed was read in an *earlier* window, so the model saw *"…scripts/tests… → edit"* without the code it was editing. At inference, after reading a file, the model has rarely been shown that the next move is an edit. Step D shows exactly that: reads and tests, never an edit.
3. **The training signal is mostly the teacher's verification scaffolding.** 56% of supervised tokens write new test, reproduction and verification scripts. Only 17% are source fixes, and only 5% of supervised actions are fixes. One epoch of this pushes the policy towards verification-style activity, consistent with Step D's pytest-heavy runs.
4. **The batching is not in the data.** It must come from somewhere else, such as decoding or an interaction with the adapter, and needs separate investigation.

## Implied data fixes (proposals; not implemented)

- **State-preserving windows:** every window that supervises an edit must contain that file's most recent read. Achieve this by packing or by dropping intermediate steps. Otherwise exclude the edit from the loss rather than train it ungrounded.
- **Rebalance:** down-weight or mask scratch-file writing (`write_file` to new test, repro or verification files). Make sure source-edit windows carry a substantial share of the loss.
- **Keep the decision text:** keep Qwen's `think` and prose as a short line before the next call, the decision points the converter dropped.
- **Behaviour gate before any eval:** a candidate adapter must produce real source edits and non-empty patches on a handful of fixed prefixes (research report E3) before a full evaluation.
- **Still open:** E1, replaying converted edits on the real repos to check the synthesized "success" responses.

## Reproduce (Atul)
The artifacts are in git as `data/runs/step_c_preprocessing_20261016.tar.gz` (6.9 MB, SHA-256 `9fab524d6b78a8670f8b2798f90f731a8339567ecda33c0815116ba6adf30b7c`). The archive holds the 200 converted traces with `convert_report.json`, `public_200_windows.jsonl` and `train_public_200.json`. The NPZ is already in git.

1. Unpack the artifacts:
```bash
tar -xzf data/runs/step_c_preprocessing_20261016.tar.gz -C data/runs
```
2. Fetch the tokenizer (not committed). Check the hashes against the E0 table above:
```bash
mkdir -p data/g4tok && for f in tokenizer.json tokenizer_config.json chat_template.jinja; do curl -sL -o data/g4tok/$f https://huggingface.co/google/gemma-4-31B-it-qat-q4_0-unquantized/resolve/main/$f; done
shasum -a 256 data/g4tok/tokenizer.json data/g4tok/chat_template.jinja
```
3. Create the tokenizer-only venv (no torch):
```bash
python3 -m venv .venv-tok && .venv-tok/bin/pip install "transformers==5.13.1" "tokenizers==0.22.2" jinja2 numpy
```
4. Run both audits:
```bash
.venv-tok/bin/python posttrain/audit_pipeline.py e0 --traces data/runs/public_200 --windows data/runs/public_200_windows.jsonl --npz data/runs/train_public_200.npz --tokenizer data/g4tok --out data/runs/audit_e0
.venv-tok/bin/python posttrain/audit_pipeline.py e2 --windows data/runs/public_200_windows.jsonl --tokenizer data/g4tok --out data/runs/audit_e2
```
