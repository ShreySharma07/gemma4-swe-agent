# S3b: fixing what the gate found (Oct 18)

## Why

Gate v1 (`data/runs/atul_gate/gate_report.json`): S3 learned a fixed script. After a **failed** test it submitted 28/32
(base 0), after a passing test 24/24, and it edited at early prefixes 10/32 (base 0). The data explains it
(`posttrain/decision_stats.py`):

| Decision in the training data | S3 (147) | **S3b (826)** | v7 solved runs |
|---|---|---|---|
| Calls before the first edit (median) | 2 | **6** | 12 |
| 3rd call is an edit (the gate's `early` point) | 64/147 (44%) | **9/826 (1%)** | 5/82 |
| Test after the fix passed → submit | 131 | 689 | 20 |
| Test **before** the fix (pass or fail) → read/edit | 0 | **~740** | — |
| Failed test after an edit → edit again | 0 (3 → submit) | 2 (1 → submit) | 0 |

So in S3 "test → submit" was unconditional. In S3b a test is followed by submit only after a fix; before the fix it
leads to reading. A genuine "fix failed → fix again" signal is rare in solved teacher runs (11/1,150 with pytest,
49 with scratch scripts), so it can't be taught directly from this data.

## What changed (`posttrain/compact_episodes.py`, defaults still rebuild S3 byte-for-byte)

- `--explore 4`: the teacher's last 4 searches/reads of other files before the first edit (real outputs).
- `--pre-test`: the teacher's last existing-test run before the first edit (real status and output).
- `--feedback`: real test results after edits (no synthesized `| tail` success); the final run kept only if it passed; runs of test files the teacher edited are dropped.

Command: `compact_episodes.py data/runs/public_1k data/runs/s3b --feedback --explore 4 --pre-test`.

## Gate fix

`kind()` matched `cat ` + word boundary, which never matches `cat -n` (so file reads were scored "other"). Fixed in
`evalkit/gate.py` and `decision_stats.py`. The gate now also stores each sampled call (`rows[].call`, 300 chars), so
"other" can be inspected. `prefixes.json` is unchanged (frozen); base is re-scored in the same session.
