## Decision

Use replay-validated, state-preserving supervised training as the first candidate **after** recovering and auditing the original preprocessing artifacts. Prefer a small causal ablation over changing the objective, rank, learning rate and data together. DPO is a later option for verified feedback decisions. ## Evidence and literature: what transfers, what does not

* SWE-Gym provides 2,438 executable Python issue environments; its authors report up to 19 absolute points of improvement and 32.0% SWE-bench Verified with trained agents plus verifiers. This supports executable successful trajectory learning, not copying its numerical gains to Gemma, private repositories, 8k windows or this scaffold. [ICML primary paper](https://proceedings.mlr.press/v267/pan25g.html).
* SWE-smith reports 50k generated instances from 128 repositories and 40.2% pass@1 for SWE-agent-LM-32B. This supports diversity and executable data synthesis; it does not demonstrate that every converted tool call remains executable or that more data repairs malformed supervision. [Primary paper](https://arxiv.org/abs/2504.21798).
* R2E-Gym reports 34.4% pass@1 for its 32B model; 51% uses hybrid test-time scaling and must not be represented as a single-run training gain. Its analysis identifies weaknesses in both execution-based and execution-free verification. This favors tests plus patch validity rather than narrative judgments. [Primary paper](https://arxiv.org/abs/2504.07164).
* DPO trains preferences without sampling during optimization or fitting a separate reward model. Its original evidence concerns preference tasks, not this specific missing-edit problem. [DPO](https://arxiv.org/abs/2305.18290). Current upstream TRL supports precomputed reference log probabilities, but this is **not** proof of compatibility with the pinned Gemma/FSDP/custom-loss stack. [TRL source](https://github.com/huggingface/trl/blob/main/trl/trainer/dpo_config.py).
* GRPO removes PPO's critic by comparing rewards within sampled groups; its original evidence is mathematical reasoning. If all group rewards are zero, centered outcome advantages provide no useful positive discrimination (with stabilized denominator, zero advantages). [DeepSeekMath](https://arxiv.org/html/2402.03300v3).
* SWE-RL's 70B model reaches 41.0% SWE-bench Verified using software-evolution data and lightweight similarity rewards. This is not a demonstration that end-to-end tool-using test-reward GRPO fits four L4s, nor that patch-text similarity is an adequate reward for live filesystem behavior. [SWE-RL](https://arxiv.org/abs/2502.18449).
* QLoRA establishes frozen NF4 base plus low-rank adapter training, including a 65B model on a single 48GB GPU; it does not establish equivalence between our NF4 training base and the scorer's distinct W4A16 quantization. The local measured envelope is more relevant. [QLoRA](https://arxiv.org/abs/2305.14314).

## Objective accounting detail from code

`MaskedCE.forward` returns sum loss / number of supervised tokens **per window**. `Trainer.run` divides each window loss by accumulation count and FSDP averages across ranks. Therefore a token in a 50-supervised-token window can receive more weight than a token in a 1,000-supervised-token window, other things equal. Validation instead reduces loss×supervised-count and divides by total supervised count. This is a code-established train/validation weighting difference, **not** evidence of a bug or the failure's cause. The audit should report (a) raw token shares, (b) action/window shares, (c) sum of 1/n_supervised per phase under the exact schedule. A proposed phase objective must explicitly choose token, action, window or task normalization and account for duplicate overlapped targets. Do not infer effective edit learning solely from the 16% supervised-token fraction.

## Recommended staged design

1. Recover exact preprocessing evidence and pass CPU replay/mask/state gates. Label phases with executable state, including first real source edit, latest source diff, test result and remaining budget. A successful source edit means a tracked repository source delta, excluding fixture-only and test-only changes. A finish target requires the actual current diff; never substitute teacher stored patch size for executed state.
2. Build a compact complete-loop baseline covering locate→edit→test→repair→submit. Keep navigation sufficient to ground edits. Later windows require actual observable state: recent file excerpts, actual diff, last test result, remaining budget; no future gold information. Recovery examples should include a failed exact-match replacement, failing targeted test, empty diff after attempted edit, and environment test failure, with truthful reactions.
3. Evaluate fixed decision-state probes before full issue runs. States: source located/no edit; failed replacement; failing regression after edit; empty submission; positive diff with passing relevant tests. Require one feedback-conditioned action at a time. A ready-to-edit benchmark intentionally provides adequate source context; it is not proof of localization skill.
4. Train one corrected-data SFT candidate in the existing r16/alpha32 envelope, if authorized. Hold objective/hyperparameters fixed initially if the identified defect is data, so data effect remains interpretable. Use phase weighting only as a subsequent controlled ablation. Separately inspect early versus final checkpoints if magnitude was implicated.
5. Extend to DPO only when matched-state positives/negatives exist; extend to RL only when the policy already edits, reward passes controls, and compute permits sustained rollout/update/evaluation.

## Behavioral gates and measurable outcomes

Proposed thresholds are engineering rejection criteria, not published guarantees. First use four deterministic small repair fixtures (one direct edit, failed replacement recovery, failed-test repair, empty-submission recovery). Require 4/4 tracked source changes, 4/4 nonempty captured patches, no unsupported success after zero diff, and no first-turn multi-call flood. Correctness still requires targeted tests; an arbitrary nonempty patch is a failure.

Then use a preregistered 12-case repository-disjoint pilot with identical seeds/scaffold/base and candidate: reject candidate with zero source edits, any systematic format break, or regression in nonempty-patch rate. Log first-source-edit turn, calls before first edit, edit→test transitions, repair after failure, correct nonempty submit, parse errors, max batch size, repeat proposal rate (separately from execution), context and runtime. Small samples only detect catastrophic regression; report exact paired counts and McNemar where outcome labels support it. A 4-task-per-arm preflight costs approximately 1.2–2 quota h by diagnosis planning, excluding any training; a larger paired pilot requires a new estimate and authorization.

Full release comparison needs matched tasks and repo-disjoint evaluation, resolved rate as primary, with no degradation in nonempty-source-patch rate. Preserve official submit semantics in evaluation; an external gate can reject the candidate without redefining success. Context arithmetic must include a safety margin below 32768 and the output reserve. Empty-patch guards and larger budgets cannot themselves supply a missing edit policy.
