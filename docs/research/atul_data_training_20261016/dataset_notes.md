# Agent 1 — Dataset design research (Atul Baliyan contribution, 16 October 2026)

This is a design proposal, not an implemented correction or experimentally validated improvement. I read the complete Step D diagnosis before researching. I did not repeat its forensic investigation, load a model, execute saved commands, or alter training artifacts. Primary project evidence is `docs/step_d_failure_analysis_20261016.md`, particularly §§2.6–2.8, 4–6. Static source inspection is additional evidence about current code, not proof of what every original Step C training example contained.

## Main finding

The existing selection rule already prefers successful trajectories. Therefore “train on successes instead” is insufficient. `posttrain/convert_public.py:284–288` requires teacher `resolved` and a submitting exit status and excludes the four public evaluation repositories. It also caps converted calls at 40 (`:235`) and optionally deduplicates by issue (`:290`). What it does NOT require is an independently observed tracked-source delta from the converted actions, recovery after misleading feedback, a causal state at each training-window boundary, or balanced action-level supervision.

The report establishes no identified source editing in D, while B produced three nonempty patches through the same scaffold. It does not establish that edits are rare in C's supervised tokens. Exact phase/token counts require original trajectories, rendered windows and tokenizer; do not replace missing counts with estimates from D's behavior. Public-source scale and a `resolved` label cannot certify converted execution fidelity.

## Specific observations and limitations

1. `convert_public.py:195–213` constructs editor commands and their success/error messages without executing them. Create responses always report success; replacements infer success from teacher text; insert similarly infers success. `:229–234` computes final submission feedback from stored `model_patch`, not the actual converted filesystem. The model may be trained on trustworthy original outcomes transformed into an unverified new action channel. This is a validation gap, not proof that any of the original 200 examples were false.
2. `convert_public.py:159–163` drops think/task-tracker operations and keeps a final summary; assistant prose is not retained. This matches thinking-disabled serving in intent, but any externally maintained plan/state needed by later actions may be removed. Do not reintroduce hidden reasoning wholesale: preserve only observable task state and evidence needed for each next action.
3. `render_atif.py:28–58` removes drifted calls AND their tool responses while retaining later steps. For recovery trajectories, deletion can erase why a corrected action was necessary. It can also leave later actions dependent on effects of a dropped call. This is a static risk; the 50-example converter sample previously had zero drift, so its impact on C is unknown and may be zero. Prefer retaining failed action and truthful result as masked context while supervising a valid recovery, or rejecting the affected span if correct context cannot be preserved.
4. `render_atif.py:107–129` creates later windows from the original task prefix plus later steps, without prior edit history. A fresh issue followed by tests/submission is therefore possible by construction. It must be measured in exact rendered artifacts. A summary must be derived from prior observations only; an oracle summary containing the answer is leakage.
5. `tokenize_windows.py:30–33` uses a task-level random split. This prevents the same issue across train/validation, but does not enforce repository/fork separation. C's ten validation tasks measure a narrow held-out text distribution; they do not establish unseen-repository generalization. The four-repository exclusion is a useful protection already present, but is not a comprehensive duplicate/fork/content audit.
6. Current `convert_report.json` fields (`convert_public.py:305–306`) record counts and median calls, not replay fidelity, first source-edit position, recovery class or token/gradient phase exposure. A low language loss can thus coexist with a failed read→edit transition without contradicting the existing diagnostics.

## Dataset construction proposal

Use a versioned pipeline: raw trajectories → provenance verification → source-edit replay → behavioral labeling → quality filtering → state-preserving rendering → token/mask validation → training → serving smoke → edit-behavior gate → independent evaluation.

- **Raw/provenance:** keep original record, dataset revision/content hash, trajectory ID, issue ID, repository URL, base commit, original model patch, teacher/scaffold/version/config, license and environment image digest. Retain the original resolved flag separately from all new verification statuses. Join source records to executable environments by exact instance ID; do not silently use current repository HEAD.
- **Replay:** after separate authorization, replay reviewed converted trajectories in disposable isolated source environments with network disabled, bounded commands and no credentials. First compare original and converted editor operations on the same snapshot, then full trajectory state changes. Original patch applies is a weaker check than converted actions reproduce it. Record per-action tracked-source before/after hashes and final normalized diff; separately label scratch files, tests/configs, staged/untracked/source-reverted edits. Exact patch agreement can reject a formatting-only difference, so define accepted normalization narrowly in advance and test patch semantics separately. Never derive success from the phrase “has been edited.”
- **Environment validity:** verify base fails the intended regression and reference fix passes before using task resolution as a label. Then apply candidate patch in a fresh environment and run independent tests. Keep infrastructure failure distinct from failed solution; changed tests or runner configuration must not create a false positive. This is proposed CPU/container work, not done in this research pass.
- **Label actions and transitions:** semantic categories include issue understanding/localization, source read, reproduction, source mutation attempt, observed successful tracked-source mutation, targeted test, broad test, failure recovery, diff verification, submission and final narrative. Labels may overlap (a shell command can edit then test); record sequence positions. A `write_file` call is not automatically a source edit, and a `run_command` call is not automatically a read. Instrumented deltas outrank lexical heuristics. Include attempted/executed/failed/budget-rejected distinctions.
- **Select episodes:** a primary positive episode must contain an observed relevant source modification, appropriate test feedback after its last edit, a nonempty scorer-eligible diff and verified resolution. Keep a separate diagnostic category for nonempty but unresolved patches; do not SFT their final completion claims as positive behavior. Preserve short successful end-to-end episodes, including initial location and edit selection; an edit-only corpus can teach blind patching.
- **Recovery examples:** preserve successful trajectories that contain a failed replacement followed by rereading/correcting, failing test followed by revised edit, shell error followed by a materially corrected command, and zero-byte submission followed by state inspection/edit/resubmission. Do not SFT unsuccessful empty-submit endings. For negative actions, retain them as masked context when learning a verified corrective continuation, or use matched-state preference pairs later. Do not label an arbitrary edit better than testing: the choice depends on evidence and current diff state.
- **Counterfactual recovery:** deliberately injected failures are useful coverage but are a separate synthetic stratum. Their resulting filesystem state and subsequent successful continuation must be executed and verified. Merely substituting “patch_size=0” into a successful trace creates an incoherent state. On-policy examples would reduce distribution shift but require new inference; defer them until a bounded authorized probe.
- **Balance:** report action counts, supervised token counts, input-token cost, first-edit position, action-transition frequencies, and effective loss weights per phase. A 500-token edit and ten short reads have different call and token exposure. Normalize sampling by task/repository so a long trajectory or many attempts on one issue cannot dominate. First compare unweighted verified SFT against a modest preregistered edit/recovery emphasis at matched supervised-token or optimizer-update budgets; do not assert an optimal percentage without evidence. A first pilot should include each critical transition (read→edit, failed-edit→corrected-edit, failed-test→re-edit, empty-diff→edit, positive-diff→submit), not just more copies of easy reads.
- **State:** prefer complete short trajectories within the demonstrated 8k training envelope. For long episodes, retain the smallest causally sufficient observed prefix (issue, relevant source, previous diff, last test result, remaining budget) and train only the continuation. Prefix observations can be masked and overlapping context duplicated without duplicating target weight. A deterministic state summary is a fallback requiring train/serve consistency; do not create a summary format the live agent never sees. Drop an example if its causal prerequisites do not fit rather than silently slicing.
- **Split:** assign repository/fork families to training, behavior-development and final evaluation before selecting windows. Deduplicate issue/PR IDs and normalized patch/code near-duplicates across datasets; log temporal cutoffs. Keep the current public114 as regression evidence, not a claim of private-repository generalization. All failure examples taken from a behavior gate contaminate that gate for subsequent model selection; reserve a fresh final set.

## Recommended schema (proposal)

Use separate immutable raw records, an auditable normalized event ledger, and derived training samples. Suggested JSON fields:

- Identity: `dataset_revision`, `raw_sha256`, `trajectory_id`, `instance_id`, `repository`, `fork_family`, `base_commit`, `issue_timestamp`, `license`, `teacher_model`, `teacher_scaffold`, `teacher_config_sha256`, `environment_digest`.
- Events: `step_id`, `original_call_id`, `converted_call_id`, `role`, `tool_schema_version`, `tool_name`, `arguments`, `original_observation_ref`, `replay_observation_ref`, `executed`, `exit_code`, `phase_labels`, `tracked_source_before`, `tracked_source_after`, `changed_paths`, `diff_sha256`, `elapsed_seconds`, `remaining_budget`, `failure_kind`, `recovery_of_step`.
- Verification: `teacher_resolved`, `base_regression_status`, `reference_patch_status`, `converted_replay_status`, `patch_equivalence_status`, `fresh_environment_candidate_status`, `test_ids`, `test_result_artifact_hashes`, `scorer_eligible_patch_bytes`, `quarantine_reason`. Missing is unknown, never success.
- Splits: `split`, `split_manifest_sha256`, `dedup_group`, `contamination_checks`.
- Samples: `sample_id`, `parent_trajectory`, `context_step_ids`, `target_step_ids`, `state_snapshot_ref`, `summary_provenance`, `rendered_text_sha256`, `tokenizer_revision_sha256`, `chat_template_sha256`, `tool_schema_sha256`, `input_token_count`, `supervised_token_count`, `phase_token_counts`, `label_mask_sha256`, `truncation=false`, `sampling_weight`, `quality_tier`.

Schema validation cannot prove semantic correctness: referenced evidence must exist, hashes must match and replay/independent tests must substantiate claims. Unknown/unreplayed examples belong in quarantine or an explicitly lower-confidence stratum, not a fabricated verified tier.

## Dataset alternatives against this failure

| Data option | Fit to missing-edit problem | Main risk | Priority |
|---|---|---|---|
| Existing public200 with faithful state/rendering and verified converted edits | Cheapest controlled test of concrete pipeline defects; preserves source/task mix | Exact original preprocessing artifacts absent; simply rerunning same success-only data may repeat D | First, if a defect is demonstrated |
| Curated verified short end-to-end + recovery episodes | Explicitly teaches observation→edit→test→correct→nonempty submit | Curation/replay effort; overemphasizing editing can reward unnecessary changes | Best subsequent dataset redesign |
| Own successful v7 trajectories | Most faithful tool/scaffold distribution; B provides proof edits can be represented | 82 successes from only 21 tasks, evaluation overlap, poor breadth and empty-submit habits elsewhere | Small behavior-preservation stratum, never final eval |
| Large unchanged public trajectory mixture | Breadth and original execution labels | Longer policies, scaffold mismatch, unknown converted fidelity; more data multiplies systematic defects | Defer |
| Synthetic patch-only issue→diff | Cheap direct edit supervision | Omits locating, actual tool use, test recovery and submission state; cannot independently solve D workflow | Auxiliary only, not primary |
| Executable synthetic bugs with existing tests (SWE-smith style) | Controls source-edit outcomes and can produce short low-cost tasks | Synthetic fault distribution and teacher cost; full regeneration unnecessary | Select existing verified assets, not build massive pipeline |

## Primary external sources and careful interpretation

1. [Nebius dataset card at pinned revision](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories/blob/ebb5599ac2b045fe09e98540519bfc60a53d8e0f/README.md): Trofimova et al., 2025. Exposes trajectory/instance IDs, original patches, resolved labels and generated-test validation fields; instance IDs join to SWE-rebench environments. Its explicit recommendation to deserialize tool arguments reinforces canonical train/serve formatting. These are source metadata, not verification of our converted examples. CC-BY-4.0 designation is recorded; preserve attribution.
2. [Nebius original technical report](https://nebius.com/blog/posts/openhands-trajectories-with-qwen3-coder-480b), 23 Dec 2025: reports 67,074 trajectories, 32,161 successes, patch-applicability filtering and RFT at 131k maximum sequence length. On their 484-task SWE-bench Verified subset, Qwen3-30B RFT reports 49.7% pass@1 at 100 turns and 50.3% at 500. SWE-bench repositories were excluded from their training, but pretraining contamination remains unproven. Different model, OpenHands scaffold and enormous context/call budget prevent importing those gains into our 8k training / 40-call serving setup. The same source's success is counterevidence to blaming the raw dataset categorically.
3. [SWE-smith official training guide](https://swesmith.com/guides/train_swe_agent/): explicitly evaluates generated patches, identifies resolved instances, converts those trajectories, then fine-tunes. Supports environment-grounded selection before SFT; it does not establish our converted action equivalence. It primarily supports SWE-agent scaffolding and describes Modal training; this is a data-construction pattern, not a compatible Kaggle recipe.
4. [SWE-smith official assets](https://swesmith.com/getting_started/assets/) and [paper](https://arxiv.org/abs/2504.21798): 128 repository environments, 50k+ tasks and a 5k expert-trajectory Qwen2.5-Coder-32B result of 40.2% pass@1 are author-reported. Useful alternative executable synthetic task source; no expected Gemma gain is inferred.

## Best next experiment

Obtain the original selected trajectory IDs/raw rows, conversion report, ATIF traces, rendered JSONL, exact tokenizer/template/tool schemas and source revisions. Run a zero-GPU dependency/phase/mask audit, producing a table per example that connects original source edit → converted action → observed result status → window location → supervised token range. Inspect all 200 metadata rows, and manually validate a deterministic diverse sample covering replacements/inserts/creates, recovery, empty stored patches, late windows and near-8k lengths. This can falsify multiple upstream hypotheses without spending the last 2.88 quota hours. Any execution replay or correction implementation still needs separate authorization. If exact reconstruction cannot be proven, label the new dataset a reconstruction and retain the original hash; never claim it is the original C corpus.
