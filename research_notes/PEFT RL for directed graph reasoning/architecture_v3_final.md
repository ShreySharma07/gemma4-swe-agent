## 0. What survived, what died, and the honest shape of the method

**What died in v2:**

| Claim | Killed by |
|---|---|
| "Twins cancel all wiring-blind credit" | L-01: they cancel only features that differ between the two gold nodes v and v′ |
| "Pairing is a new RL mechanism" | CRPO 2605.21988 (closeness 2.5), CAD, Teney ECCV'20, PairCFR; and L-02: in expectation, pairing equals an unpaired real+null mixture |
| "The agent RFT stage trains wiring use" | L-03 (fitted shims solve both twins) and L-07 (1–2 optimiser steps) |

**What survived both prior-art passes:**
- real-vs-null topology used as a **training-data** variable (`break_v1_priorart` §4, reaffirmed in `break_v2_priorart` §3.4);
- graph-null-model construction of the counterfactual (`break_v2_priorart` §3.1).

**The breakers' own insight, turned into the new piece (L-01 lead).** Training against a null model removes credit **only for the statistics the null does not preserve**. The null's preserved set S therefore *defines* which structural shortcuts remain learnable. A **nested family of nulls** is then a dial:

- **far**: per-type degree only;
- **mid**: degree + longest-path level;
- **near**: degree + level + module block;
- **leak**: edge count only.

Each step down the dial removes a known family of topology statistics from the set of reliable cues: motif/wiring detail, module locality, depth/level, and degree.

> **Single novel claim [CLAIMED].** Fine-tuning an LLM on execution-labelled counterfactual items generated by a **nested family of graph null models** applied to real traced program graphs acts as a **controllable dial over which topology statistics the model relies on**. Reliance on a statistic family (module locality, depth level, local motifs) falls **when, and only when**, the training null destroys that family. This is measured by prior-versus-displayed-edge conflict probes on held-out real code.

**Method and naming, honestly** (requirement 2):
- On 4×L4 the method is **execution-labelled item SFT** (PEFT/LoRA). Each item's labels are verified by running the compiled program, which is a verifiable reward used as a supervised target.
- **RL-style training (RFT/GRPO) appears only as a specified online drop-in** for hardware with an online RL stack (§6). It is **not run here**.
- The paired-twin item recipe is the [KNOWN] CRPO/CAD mechanism. The null-order dial and its reliance readout are the [CLAIMED] part.

## 1. The falsifiable claims, with effect sizes and honest power

**Two primary families, each at α = 0.025** (Bonferroni across the two families). Within a family, testing is a fixed sequence.

### Family A: method (does null-twin training improve graph reasoning?)

- (a) every trained arm beats base on held-out synthetic items **in its own world** by ΔAP ≥ +0.05;
- (b) the positive control **P** beats base on E1 (real items, real context) by ΔAP ≥ +0.03.

### Family B: the novel dial (shortcut spectrum)

Statistic families f:
- **Loc**: same module as the test's direct callees;
- **Lev**: level or distance adjacency;
- **Mot**: co-called-with-a-known-callee and transitive-triangle cues.

Each family is operationalised by a CPU topology-only classifier (kill K-C3).

**Reliance_f(model)** = on E2 elements where family f's prior **conflicts** with the displayed-edge label, the mean signed score toward the prior. It is 0.5 when indifferent, higher when the model follows the prior.

## 2. Architecture

### 2.1 Pipeline

```
CPU ───────────────────────────────────────────────────────────────────────────────────────────────
S_topo (6–8 non-dev repos) ─► C1 tracer (setprofile+threading, code-object id, unique-resolution typing)
   ─► C2 hygiene (integration roots, task-wise growth, SCC cap / bounded recursion, effect-only edges,
                 dead code, hub cap)  ─► real DAG G
   ─► C3 NULL FAMILY [CLAIMED use]: ρ_near (deg+level+module), ρ_mid (deg+level), ρ_far (deg),
        ρ_leak (edge count); lexical+callback edges; pre-registered min rewired fraction; registry-key
        swaps allowed (L-13); NO family constraint (common value domain, arity only; L-11)
   ─► C4 compiler [KNOWN pattern]: total templates over ONE value domain; random names, independent of
        topology, same seed across worlds; no docstrings; positional calls
   ─► C5 twin items: test t + pool of 16, path-complete in BOTH wirings (L-14), ≥4 discordant elements,
        labels = executed call set (= static reachability in compiled worlds)
   ─► audits K-C1…K-C7 (§8, day-1 kills)
S_eval (16–20 non-dev repos, disjoint) ─► C9 real items: path-complete, static/trace agreement filter,
        hub cap, mocks out; contexts E1 real, E2 conflict-rewired (displayed labels), E3 graph-free,
        E5 RepoMirage-style indirection (label-preserving); FROZEN + SHA-256 before trained-arm eval
S_ctrl (= S_topo real code) ─► P items (real bodies, trace labels, same format)
GPU (4×L4) ────────────────────────────────────────────────────────────────────────────────────────
C6 trainer: FSDP + bnb NF4 (quant_storage=bf16) from dequantised W4A16; packed 12k sequences with
   block-diagonal + unary 4-D masks; LoRA r=16; 26 adapters (arms × seeds), ≥1,000 items each
C7 evaluator: vLLM W4A16 + multi-LoRA (served stack); unary per-candidate queries sharing a cached prefix;
   continuous score = expected level from renormalised level-token log-probs
C8 agent-world descriptive (G2): deployed V5 pipeline, deployed sampling, hidden per-node contracts
```

### 2.2 The null family (C3)

All nulls act on lexical and callback edges. Registry-key swaps are also allowed: string constants are exchanged within one registry, which keeps the class structure (L-13). Dispatch and decorator edges stay fixed. Swaps are directed double swaps (a→b, c→d) ⇒ (a→d, c→b), with no self-loops, no multi-edges, and acyclicity enforced. All callees share one total value domain (bounded ints), so **arity is the only compatibility constraint**. The family constraint is dropped (L-11, K-15 resolved by the common domain).

| Null | Constraint on proposed swaps | Preserves | Destroys | Pre-registered minimum rewired fraction J = 1 − \|E_G ∩ E_ρ\| / \|E_rewirable\| |
|---|---|---|---|---|
| ρ_near | level(a)=level(c), level(b)=level(d), module(b)=module(d) | per-type degree, levels, module-block counts | within-block wiring, motifs | **≥0.30** |
| ρ_mid | level constraints only | degree, levels | module locality, motifs | **≥0.50** |
| ρ_far | none beyond acyclicity | degree | levels, locality, motifs | **≥0.80** |
| ρ_leak | edges re-drawn uniformly at random, keeping \|E\| and acyclicity | edge count | degree sequence too | ≥0.90 |

**Reporting.** For each source graph and null: J; modularity Q; intra-file fraction; the level histogram; triangle, diamond and feed-forward-loop counts; in/out-degree KS; and the per-node count of roots reaching it.

**Source graphs** are kept only if **every** null reaches its minimum J. No source is dropped selectively from some arms (K-23 logic). The drop count is reported (K-C1).

### 2.3 Items (C5)

**Structure.**
- One test t (an integration root) and a pool of 16 candidates.
- Bodies ≤6 lines from total templates; ≈0.75k tokens per item including the unary suffixes.
- **Path-complete in both wirings:** every edge on every reach path to every pool element is shown (L-14).
- ≥4 discordant elements per twin pair (CALLED in one world, NOT in the other). **Concordant elements are kept** and also trained.
- Labels are the executed call set. In compiled worlds this equals static reachability, because calls are unconditional and templates are total.

**Format** (one format for training and evaluation, which fixes K-41 and K-36): the item prefix, then per candidate a separate unary query `"<qualname>: CALLED p="`. The answer is one of the 5 level tokens {0.05, 0.2, 0.5, 0.8, 0.95}.
- **Training** packs the prefix once, followed by 16 unary suffixes. A 4-D mask lets each suffix attend to the prefix and itself only, so no other label is visible.
- **Evaluation** sends 16 vLLM requests that share the cached prefix.
- The score is the expected level under the renormalised level-token distribution, giving 100% parse for every model.

**Dose:**
- **1,000 items per adapter**, i.e. **16,000 supervised labels** (L-22).
- ≈0.75M tokens, packed into 12k sequences (≈62 sequences per epoch).
- Effective batch 4 sequences ≈ 64 items ⇒ **≈16 optimiser steps per epoch, 2 epochs = 32 steps**, warm-up 3 steps (≤10%) (L-07).
- Pools are drawn **without replacement** from a generated reservoir of ≥5,000 pools per world type. Each seed draws a distinct sample, and the unique-pool count is reported (L-27).

**Untrained baselines:**

### 2.5 Agent worlds (G2 and the drop-in only): the L-03 and L-10 fixes

- **Hidden per-node contracts** run on fresh random inputs for **every node in the failing contract's subtree, including the bug node**. Hidden P2P covers every non-bug node. Reward then equals "restore the bug node, change nothing else" (L-03).
- C5 keeps an alternative-fix library for all operators: revert, ancestor fit-and-replace, compensating parent edit, and shim. A task is accepted only if none of these passes.
- **Observation-free fitting solver** audit: its pair-both rate must be ≤0.05 (K-C7).
- **Bug operators are limited to identifiable repairs** (L-10):
  - O1 = an operator flip among ≤3 options;
  - MCR = a single-site call-target replacement whose correct callee is unique among arity-compatible candidates given the contracts.
  - There is no constant inversion.
- **Deployed V5 SequentialAgent** with deployed sampling (T 0.2, top-p 0.95, top-k 40) and the deployed tool and step caps.

## 3. Objectives

All losses act on level tokens only, using a **per-stage mean over supervised tokens** rather than a 16k constant (L-27). Adam ε = 1e-10.

**Item SFT (all arms except M_rel's null half):**

`L = −(1/|S|) Σ_{(item,v)∈S} log π_θ(ℓ(y_v) | prefix, suffix_v)`

- ℓ(1) = the 0.95 token and ℓ(0) = the 0.05 token, with label smoothing 0.1 onto the adjacent level. This is the log score of the verbalised class.
- lr 1e-4, cosine, 2 epochs.
- Twins are never placed in the same packed sequence (PairCFR warning). M arms shuffle twin halves independently.

**M_rel (CRPO-style relation baseline).** Real halves use L as above. On the null half, which has no labels:

`L_rel = −log σ(κ·(d(ŝ_real, ŝ_null) − m))`

- d = mean |Δ expected level| over the pool, between the model's scores on the two halves;
- m = 0.15, κ = 10.
- This rewards the null half for *answering differently*, as CRPO's relation reward does for dynamic questions, without using null labels.
- Note: CRPO knows only *that* the answer should change. The item analogue likewise knows only that the set should change, not which elements.

**Online-GRPO drop-in (other hardware; specified, not run).**
- **Batches:** twin-balanced; both halves of every pair are in every batch.
- **Advantages:** `A = R − mean over the pair's 2K samples`. **No std normalisation** (Dr.GRPO-style). This keeps the twin property that no blind guess between v and v′ is preferred (L-05, L-25).
- **Reward:** binary under hidden per-node contracts and P2P.
- **Importance weights:** truncated, `min(π_train/π_vLLM, 2)`, with masking when |log w| > 1.
- **Sampling:** deployed temperature and top-k, with the same logit transform in the trainer.
- **Warm start:** the item-SFT adapter (Stage A).
- **Optional additive terms:** Z penalty and CERT credit.
- **Rejected alternative:** CRPO's cross-branch relation reward. Per-twin verified gold exists, so the relation adds no information. It also couples the two branches and leaks pair identity into the reward.

## 5. Retention and near-SOTA (requirement 3; L-21)

**Primary (powered, continuous, paired):**
- (i) **Exact per-token KL** over the full vocabulary between adapter and base, on 20 held-out base agent turns plus 200 SWE-V prompts. Gate: mean ≤0.03 nats, p99 ≤0.5.
- (ii) **Gold log-probability margins**: MMLU-Pro 1,000-item slice, log p(gold) − max log p(distractor); non-inferiority margin −0.05 nats.
- (iii) **HumanEval+ gold-solution per-token NLL**: Δ ≤ +0.02 nats.
- (iv) **Tool-call turn NLL** on 1,000 held-out deployed tool-call turns: Δ ≤ +0.02 nats.

With paired SD ≈0.3 nats and n = 1,000, SE ≈0.01, so P(pass | true Δ = 0) ≈ 1.

**Descriptive:** MMLU-Pro accuracy and HumanEval+ pass@1 for base and M_mid seed 1.

**Reference point (no API; Shrey dropped the API route on 30 Sep):**
- **Conditional C1:** serve the bf16 `gemma-4-31B-it-qat-q4_0-unquantized` checkpoint in vLLM TP = 4. That is 15.6 GB per GPU, leaving ≈4–6 GB per GPU for KV, which is enough for ≤3k-token items. Score it on E1/E2/E3 and SWE-V with the same unary readout (0.7 GPU-h central). Prerequisite: upload the 62.5 GB checkpoint as a Kaggle dataset (CPU and network only).
- **Otherwise:** a **published-number comparison** only, using the TraceEval slice in its native metric against TraceEval's reported models. This is labelled as a weak, different-model comparison.

## 6. Generality (requirement 5)

**Scope of the claim.** Executable graphs (call graphs, build or workflow DAGs) whose **node content is uninformative about wiring**: either by construction, as in the compiled worlds, or verified by K-C4. Real code violates that assumption (L-26). The claim about real code is therefore only about *reliance shifts measured on real code*, not that real-code twins are valid.

**Negative name transfer** is measured, not assumed. E1/E2 are stratified by "name-informative" elements, where a name-only classifier is confident, with the prediction M_mid − U ≤ 0 there.

| What | Transfers? |
|---|---|
| The null family, the item format, and the reliance–conflict readout | Model- and hardware-agnostic (pure data and evaluation) |
| Dose rule | Scale items until the positive control passes GW(b). Keep seeds ≥5 on headline arms; seed is the unit |

## 10. Statistics (L-17)

**Unit.** Seed is the unit for every arm term. All arms are evaluated on the same frozen items.

**Primary model:**

`score ~ arm + (1|seed:arm) + (1|repo) + (1|repo:item)`

with **Kenward–Roger df**. The sensitivity analysis is Welch's t on seed means with Satterthwaite df. A wild-cluster bootstrap-t over repos (Webb weights) covers item generalisation.

**HS tests** are seed-level regressions of Reliance_f on break/keep, with Holm correction over the three families. HS-spec uses TOST on seed means.

**Pre-registered before any trained-arm evaluation:** item hashes, sampler seeds, conflict-family classifiers (frozen after K-C3), arm–family design matrix, margins, the gatekeeping order, and every numeric trigger.
